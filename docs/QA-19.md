# QA: Backlog #19 Video difficulty estimate

## Scope

Backlog #19 closes the existing video-difficulty implementation from PR #47. The estimate remains a local, deterministic guide on the Watch/Study surface. It does not block video or transcript access and does not claim precise comprehension.

The closeout also fixes the difficult-content notice so a learner-state estimate is described as `personalized` rather than `starter`.

## Acceptance evidence

| Criterion | Evidence |
| --- | --- |
| Approximate difficulty shown | `VideoDifficultyEstimateView` renders the `beginner-friendly`, `intermediate`, or `challenging` band. Domain tests cover band inputs and the browser diagnostic confirms the visible region. |
| Approximate likely comprehension shown | The domain returns a bounded range and the UI labels it `Likely comprehension`; component and browser checks cover the rendered range. |
| Estimate uses learner state when available | `loadVideoDifficulty` reads saved learning items through the storage boundary. The domain weights known and learning-item recognition confidence, avoids overlapping phrase/word double-counting, and returns `source: "personalized"`. |
| New-learner fallback exists | Empty learner state uses transcript length and repetition signals, returns `source: "fallback"`, and renders honest starter copy. |
| Difficult content remains accessible | The estimate states that the full video and transcript remain available. Challenging content uses a non-blocking notice with Continue and Dismiss actions; the browser check confirms the transcript remains visible. |
