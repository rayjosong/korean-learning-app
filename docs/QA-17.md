# QA - Backlog #17 Mixed review modes

## Audit result

Backlog #17 was already implemented in commit `620a41df97a7e7c00b0c192b2a64f9de7cb510b1` (`Add mixed review modes (#31)`). The backlog top-level checkbox was checked, but its five acceptance-criterion checkboxes were left stale.

## Acceptance evidence

| Criterion | Evidence |
| --- | --- |
| Recognition mode | `ClozeReviewPanel` exposes `recognition` as a selectable review mode and uses the source sentence for recognition recall. Component coverage asserts the mode is rendered. |
| Production mode | `ClozeReviewPanel` exposes `production` as a selectable review mode. `applyReviewOutcome` routes production outcomes to `productionConfidence` only. |
| Cloze mode | `ClozeReviewPanel` defaults to `cloze`, masks the learned item in the source sentence, reveals the answer, and records the outcome. |
| Review type stored | `ReviewMode` is `recognition | production | cloze`; `completeReview` persists the selected mode in each `ReviewRecord`; Dexie indexes `reviewRecords` by `mode`. |
| Recognition/production confidence tracked separately | `LearningItem` stores both confidence values. Recognition/cloze reviews update recognition confidence; production reviews update production confidence without changing recognition confidence. Domain tests verify the separation. |

## Existing regression coverage

- `apps/web/components/cloze-review-panel.test.tsx` verifies the mixed-review surface exposes recognition, production, and cloze modes and protects cloze masking.
- `packages/learning-engine/test/cloze-review.test.mjs` verifies cloze/recognition confidence updates and that production confidence changes independently.
- `apps/web/lib/complete-cloze-review.ts` persists the selected review mode and learner-state update in one transaction.
- `packages/storage/src/index.ts` defines durable `ReviewRecord.mode` and the review-record index.
